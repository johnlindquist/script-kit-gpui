# The Branch Is a Claim, Not a Result

*An evidence-first audit of 50 predominantly AI-authored commits and 481 changed paths: what improved, what may have broken, which claims remain unproven, and the exact work required before the branch deserves trust.*

**Audit date:** August 8, 2026 · **Candidate:** `a3fc52549` · **Base:** `3775672d2` · **Disposition:** blocked from merge confidence, ready for human review of this audit

## 50 Commits, 481 Paths, and a Trust Problem

The branch is not small. Against its merge base with `main`, `consistency/default-recommendations` contains **50 commits**, **481 changed paths**, **73,667 insertions**, and **13,925 deletions**. The change spans shared UI, launcher surfaces, Agent Chat, protocol types, Flow, Notes, Dictation, window automation, tests, probes, generated design data, and the evidence system that was supposed to prove the other changes.

That last category matters most. The branch was built largely by AI agents, and much of its confidence story was also written by AI agents. AI authorship is not evidence of failure. It is also not evidence of correctness. A green ledger, a polished receipt, or a confident summary can be useful—but only after an independent check binds it to the current candidate, the correct task, the real producer, and the layer where the claim lives.

The six audit packages accounted for the full delta: shared UI owned 87 paths; core surfaces 128; AI and protocol 53; windows, Flow, Notes, and Dictation 45; proof and provenance 160; integration seams 8. The final reconciliation is exact: **481 expected, 481 reviewed, zero gaps, zero extras, zero duplicates**.

The integrated finding set contains **65 findings**: 27 verified improvements, 8 confirmed regressions, 7 breakage candidates, 13 proof gaps, 6 proof-debt findings, 3 unproven claims, and 1 no-material-change finding. None reached C4, the real app/native/runtime ceiling. Twenty-nine reached C3 through direct production behavior or handler tests. Eighteen reached C2 through static consumer traces or generated parity. Seventeen remain C1 mechanisms or weak proof. One historical claim remains C0.

The most important conclusion is not “the branch is bad.” It is narrower and more useful: **the branch contains real improvements, but its own proof gate can accept well-shaped fiction.** Until that gate is repaired and the highest-risk runtime seams are crossed, the branch cannot use its existing 75-of-75 story as a reason to merge.

## How We Audited Without Trusting the Audit

Every change began as a claim. Six independent planning passes divided the branch by owner; six local workers reviewed exact path lists; the manager then rejected incomplete reports, reran high-value falsifiers, downgraded overclaims, and reconciled the path union independently.

The evidence ladder was explicit. C0 is self-report or stale evidence. C1 is a concrete but unreproduced mechanism. C2 is static structure, generated parity, or a traced consumer. C3 is direct production behavior, reducer, handler, or GPUI/model testing. C4 is a real process, AppKit window, filesystem, protocol, pixel, keyboard, focus, or temporal boundary. Screenshots are capped at C2. Source-reading tests are capped at C1 for runtime behavior.

This matters because several first attempts “passed” while running zero tests. Those receipts were rejected. The manager listed compiled names and performed one corrected rerun. A cancellation test then ran exactly one test and passed. Quick Question ran 11 tests and passed. Notes handoff ran 10 tests and passed. Footer descriptors ran 2 tests and passed. The locked glass suite ran 40 Bun tests plus the named Rust fixture and passed without changing calibration values or expectations.

The audit also challenged the proof system adversarially. A forged receipt with the wrong embedded task ID, an unregistered producer, no evidence layers, and self-asserted success was placed where task `GOV-002` expected evidence. The verifier returned `EVALUABLE_PASS` and exit 0. A forged 75-task program also passed 75 of 75. A family declaration passed while pointing at a nonexistent member receipt. These are not theoretical worries; they are reproduced proof-gate failures.

No production source was edited during this audit. Hashes for all 481 frozen paths were recorded before the lanes and matched afterward. The glass-motion calibration remained locked. The app was built once into a candidate-pinned artifact and used with sandboxed fixtures for screenshots. A Notes capture exposed private content despite a generic sandbox flag; it was deleted, excluded, and not replaced after explicit test-store isolation still failed. That incident is part of the trust story: a privacy control that sounds sufficient is not sufficient until the resulting pixels are inspected.

## What the Evidence Actually Supports

### Verified Improvements

The shared UI work is substantial and often good. Row state and geometry ownership moved into shared models with direct coverage. Semantic projection now distinguishes Complete, Partial, and Unsupported instead of fabricating completeness. Buttons, forms, shortcut recording, toast identity, popup generations, conversation commands, and shared semantic states gained focused behavior tests.

Core behavior also improved. Disabled Actions are rejected before callbacks for both selected and direct-ID activation. Quick Question has an explicit no-context, no-submit constructor contract. Conversation turns retain an originating-message render identity after assistant output arrives. Flow and Notes action builders consume typed descriptors for labels, shortcuts, availability, disabled reasons, and handlers.

AI reliability gained meaningful structure. Explicit Stop becomes `UserStopped` cancellation instead of a provider failure in focused tests. Partial-output identity survives. Preflight persistence avoids raw message bytes. Context parts carry role, provenance, lifecycle, generation, and immutable receipts. Protocol elements gained redacted content and explicit projection quality.

Flow, Dictation, Notes, windows, and layout all gained behavior coverage: 141 Flow tests, 290 Dictation tests, focused Notes search and handoff tests, 31 window automation tests, and 60 layout/resize tests. The glass anti-drift contracts remain green without retuning. Footer descriptors gained stable semantic IDs and fail-closed shortcut routing. Shared row eligibility now has direct behavior coverage.

### Plausible Improvements

The screenshots support a coherent visual direction. The main launcher, Actions, Settings, Flow Desk, and Dictation overlay share row, section, shortcut, and footer language more consistently. The proof explorer clearly teaches the right principle: match each claim to its native layer.

But static coherence is not temporal correctness. A clean Actions screenshot cannot prove first focus. A Dictation screenshot cannot prove delivery. A footer screenshot cannot prove first-click dispatch. The explorer can teach truth while its generated manifest is stale. These are plausible improvements pending stronger receipts, not permission to collapse confidence levels.

### Breakage Candidates

Several exact mechanisms need runtime falsification. Settings statically assigns the verb “Open” to Clear, Check, Request, and Reset operations. Actions can evaluate auto-close before its deferred first-focus request. Agent Chat entry completion is correlated by aggregate message and context counts rather than the initiating request. Same-source context snapshots may drop changed content as duplicates. Failed Dictation projection still uses Debug formatting on a richer failure enum. Notes supplement counts, receipts, and partial deletion can disagree. Notes can claim editor focus while another panel owns focus. Footer Agent routing may inherit ambient/default-selected context instead of clean-question intent.

These are not declared observed failures unless the audit reproduced them. They are concrete `input/state → predicted wrong result` candidates with owners and stop conditions.

### Unproven AI Claims

The largest trust failure is in proof admission. Existing historical Flow receipts do not bind the current candidate, producer, binary, fixture, or evidence layer. The generated consistency manifest is independently stale in three fields. Several source-contract tests fail while others overclaim native behavior. Glossary paths are portable, but multiple retained line anchors land on unrelated code.

The branch has a sophisticated evidence vocabulary. It does not yet have a verifier that reliably distinguishes evidence from a document shaped like evidence.

## The Executable Next-Steps Program

**N01 — Repair proof admission before trusting any aggregate. Priority P0; must fix before merge review.** The branch’s headline proof can currently be satisfied by a receipt with the wrong embedded task ID, an unregistered synthetic producer, no evidence layers, and self-asserted success. A forged 75-task corpus reports 75 passing tasks, and a family can pass while referencing a nonexistent member. The owner is `scripts/devtools/consistency.ts`, `scripts/devtools/lib/receipt-schema.ts`, and the producer/task registry. The failure scenario is precise: place a well-shaped fiction beneath the expected directory and receive exit 0. The repair must bind directory task, embedded task, registered producer, current source identity, required evidence layers, and negative-control outcomes. Proof is the same manager-owned forged task, forged program, and missing-member controls. Stop only when every forgery is rejected with a typed nonzero disposition and one valid current receipt still passes.

**N02 — Make aggregate truth inherit validated member truth. Priority P0; must fix before merge review.** Even strict top-level admission is insufficient if nested family/program fields are manufactured or unchecked. Owners include `verifyFamily`, `verifyAll`, the receipt schema, privacy/interference/cleanup status, and generated-output provenance. Failure scenarios include omitted cleanup becoming `closed:true`, an unperformed canary scan appearing performed, a family passing with one missing member, or a rendered-motion claim carrying only model evidence. Add mutation controls for missing members, wrong family, stale source, wrong task, copied nested status, and absent evidence layers. Proof must show every green aggregate derives its status from individually admitted current members. Stop when changing any required member identity or evidence layer flips the aggregate to a typed failure and no aggregator invents omitted success fields.

**N03 — Reconcile the stale consistency explorer manifest. Priority P1; verify before merge and fix before publishing it as source-derived truth.** The current generator runs successfully but produces bytes different from `design/consistency/data/groups.json`. The independent reproduction found three stale fields: WF-002 owners and GOV-003/GOV-005 status. The owner is `design/consistency/tools-build-data.py`, `.notes/CONSISTENCY-FIXES.md`, and the checked manifest. The failure scenario is a reader seeing old ownership/status under a label that says source-derived while all structural and browser smoke tests pass. Regenerate in isolation, review the semantic delta, and update the source or generated output at the owning layer in a future fix. Add byte-parity to the explorer validation gate. Stop at deterministic byte equality from a clean isolated generation without rewriting evidence during the test.

**N04 — Correlate Agent Chat entry completion by request identity. Priority P0; verify before merge, must fix if false completion reproduces.** `AgentChatEntryRequest` returns structured outcomes, but current completion checks infer success from aggregate message and context-chip count growth. An unrelated message can satisfy submission; an already-present exact context can look unstaged; delayed accepted submission can be reported as timeout. Owners are `src/app_impl/agent_handoff/agent_chat_entry.rs` and the authoritative Agent Chat state snapshot producer. Run a matrix covering duplicate context, unrelated message mutation, delayed acceptance, fresh/reused threads, refusal, and real timeout. Each terminal outcome must carry request, turn, context, and submission identity. Stop when unrelated mutations cannot satisfy another request and every accepted/refused/timed-out result points to the originating operation rather than counts.

**N05 — Preserve clean-question intent across every launcher affordance. Priority P0/P1; must fix if ambient context reproduces.** Quick Question’s constructor is tested and clean, but footer Agent routes through a standard launcher policy that may admit the default auto-selected row. The failure scenario is a user asking a quick question and silently attaching “Ghostty Commands” or another first row as context. Owners are footer dispatch, `AgentChatEntryRequest`, and launcher entry policy. Run the real footer action with an empty filter and a real default selection; compare it with Quick Question and deliberate Cmd+Enter. Proof requires zero implicit context and zero auto-submit for clean affordances, while deliberate targeted entries preserve exactly one intended context. Stop when intent—not whichever row happens to be selected—determines context.

**N06 — Turn native footer automation into an end-to-end receipt. The automation result can therefore be green when no canonical action is accepted. Owners are `src/footer_popup.rs`, `src/app_impl/ui_window.rs`, and canonical footer dispatch. ## Coverage and Receipts

The audit reached exact static coverage: 481 of 481 paths, with six admitted worker reports and independent manager falsifiers. The manager reproduced the forged proof admission, generator drift, Quick Question contract, cancellation behavior, Notes handoff behavior, footer descriptor behavior, complete branch diff check, and locked glass anti-drift checks. A candidate-pinned binary was built and used for privacy-reviewed screenshots.

The merge disposition is **BLOCKED** by the false-green receipt verifier. That is not a claim that every product change is broken. It is a claim that the existing aggregate proof cannot carry merge confidence.

Runtime coverage remains intentionally incomplete. The Article/Agent Chat fixture did not expose the expected target, so no Agent Chat screenshot was admitted. Notes screenshots repeatedly exposed private content despite sandbox controls, so every Notes frame was deleted. Those are honest proof gaps, not green results.

No production fix, push, merge, application deployment, or glass retune occurred. The published article documents the branch; it does not approve the branch.
